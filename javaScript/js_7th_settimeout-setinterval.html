왜 타이머 함수가 필요한가

정해진 시간이 지난 뒤, 또는 일정한 간격마다 코드를 실행해야 하는 상황에서 사용한다.

예를 들어 알림창을 띄우고 3초 뒤 자동으로 닫거나, 화면 왼쪽 위에 있는 시계를 1초마다 갱신하거나, 스크롤 이벤트가 너무 자주 발생하는 걸 막기 위해 마지막 입력 후 300ms를 기다렸다가 검색을 실행하는 경우가 있다. 이런 "지금이 아니라 나중에, 또는 반복해서" 실행하는 일을 setTimeout과 setInterval이 담당한다.

핵심: 자바스크립트는 한 번에 한 가지 코드만 실행한다(싱글 스레드). setTimeout(fn, 1000)은 "1000ms 뒤에 fn을 실행해 달라"는 예약이지, "정확히 1000ms 뒤에 실행"을 보장하는 명령이 아니다. 그 시점에 다른 코드가 실행 중이면 그 코드가 끝날 때까지 기다린다.

setTimeout — 한 번만, 지정한 시간 뒤에

지정한 시간(ms)이 지나면 콜백을 딱 한 번 실행한다. 아직 실행되지 않았다면 clearTimeout으로 취소할 수 있다.

// 3초(3000ms) 뒤에 한 번 실행
const timerId = setTimeout(function () {
  message.textContent = "3초가 지났습니다";
}, 3000);

// 아직 실행 전이라면 취소 가능
clearTimeout(timerId);

반환값 timerId는 숫자다. 이 값을 변수에 저장해두지 않으면 나중에 취소할 방법이 없다는 점이 가장 흔한 실수다.

setInterval — 지정한 간격마다, 멈출 때까지 반복

같은 콜백을 지정한 간격(ms)마다 계속 실행한다. 직접 clearInterval을 호출하지 않으면 페이지가 닫힐 때까지 멈추지 않는다.

버튼을 누르면 while 반복문으로 메인 스레드를 1.2초간 붙잡아 둔다. 그동안 예약된 틱이 바로 실행되지 못하고 기다렸다가, 작업이 끝난 직후 간격이 1000ms보다 훨씬 크게 찍히는 걸 볼 수 있다.

// 1초마다 반복 실행, id를 저장해 두어야 나중에 멈출 수 있다
const intervalId = setInterval(function () {
  tickCount++;
}, 1000);

// 반복을 멈춤
clearInterval(intervalId);

위 데모의 "멈추는 작업"은 while (Date.now() - start < 1200) {} 형태의 빈 반복문이다. 실제 코드에서는 큰 배열 정렬, 동기적인 이미지 처리처럼 시간이 걸리는 연산이 이 역할을 한다.
