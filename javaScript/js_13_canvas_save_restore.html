캔버스 save()와 restore()

색을 바꾸고, 선을 굵게 하고, 캔버스를 돌린 뒤에 "아까 설정으로 돌아가고 싶다"면 이 두 줄을 쓴다. 그려 놓은 그림이 아니라 그리기 설정을 저장한다는 점이 핵심이다.

미리 알아야 할 것: fillStyle, fillRect(), arc(), setInterval

  • save()지금 설정(색, 굵기, 이동·회전 등)을 저장 상자에 한 장 쌓는다.
  • restore()맨 위에 쌓인 한 장을 꺼내 그 설정으로 되돌린다.
  • 그림은?이미 그린 그림은 지워지지도, 되살아나지도 않는다.

1기본 흐름: 저장 → 바꾸기 → 되돌리기

  1. ctx.save();

    "지금 설정 기억해 둬." 펜 색과 굵기를 사진 찍어 둔다.

  2. ctx.fillStyle = ...

    마음대로 바꿔서 그린다. 이 사이에서 바꾼 설정은 잠깐 빌려 쓰는 것이다.

  3. ctx.restore();

    "아까 찍은 사진대로 돌아가." 빌려 쓴 설정이 원래대로 돌아온다.

ctx.fillStyle = 'black';
ctx.fillRect(20, 30, 60, 60);    // 1 검정

ctx.save();                      // 검정 상태 저장
ctx.fillStyle = 'tomato';
ctx.fillRect(100, 30, 60, 60);   // 2 빨강
ctx.restore();                   // 다시 검정

ctx.fillRect(180, 30, 60, 60);   // 3 검정

실행 결과

3번 사각형은 fillStyle을 다시 쓰지 않았는데도 검정이다. restore()가 설정을 되돌렸기 때문이다. 그리고 2번 빨간 사각형은 restore() 뒤에도 그대로 남아 있다.

정리하면, save()는 "펜과 종이 놓는 방법"을 기억하고, "종이에 그려진 그림"은 기억하지 않는다.

3스택 실험대: 쌓고 꺼내기

저장 상자는 접시를 쌓듯이 위로 쌓이고, 맨 위부터 꺼내진다. 이런 구조를 스택(stack)이라고 한다. save()를 두 번 하면 두 장이 쌓이고, restore()는 마지막에 저장한 것부터 하나씩 되돌린다.

    4가장 많이 쓰는 곳: 이동과 회전

    translate()와 rotate()는 그림이 아니라 종이(좌표)를 옮기고 돌린다. 그리고 이 효과는 계속 쌓인다. translate(160, 160)을 두 번 하면 (320, 320)으로 간다. 그래서 무언가를 돌려 그린 뒤에는 restore()로 종이를 제자리에 돌려놓아야 다음 그림이 엉뚱한 곳에 그려지지 않는다.

    function drawFrame() {
    ctx.clearRect(0, 0, 320, 320);
    ctx.fillStyle = '#1f1f1c';
    ctx.fillRect(156, 160, 8, 150);   // 기둥

    for (let i = 0; i < 4; i++) {
        ctx.save();
        ctx.translate(160, 160);  // 원점을 가운데로
        ctx.rotate(angle + i * Math.PI / 2);
        ctx.fillStyle = colors[i];
        ctx.fillRect(0, -14, 110, 28);
        ctx.restore();            // 제자리, 원래 색
    }

    ctx.beginPath();
    ctx.arc(160, 160, 12, 0, 2 * Math.PI);
    ctx.fill();                       // 가운데 축
    ctx.fillText('바람개비', 16, 28);

    angle = angle + 0.03;
}

setInterval(drawFrame, 30);

    직접 해 보기

    체크를 끄면 날개마다 translate와 rotate가 계속 쌓인다. 두 번째 날개부터 엉뚱한 곳으로 날아가고, 가운데 축과 글자도 마지막 날개 색으로 돌아간 자리에 그려진다.

    실험을 위해 매 장면을 시작할 때 종이 위치를 초기화해 두었다. 실제로 초기화도 안 하면 장면이 넘어갈 때마다 더 멀리 밀려나 금방 화면에서 사라진다.

    5clip()을 풀 수 있는 유일한 방법

    clip()은 지금 경로 모양으로 "그릴 수 있는 구역"을 잘라 낸다. 한 번 자르면 그 바깥에는 아무것도 그려지지 않고, clip을 해제하는 함수는 따로 없다. 그래서 clip()은 거의 항상 save()와 restore() 사이에 쓴다.

    ctx.save();
ctx.beginPath();
ctx.arc(110, 100, 70, 0, 2 * Math.PI);
ctx.clip();                     // 원 안만 그려짐

for (let i = 0; i < 12; i++) {  // 줄무늬
    ctx.fillStyle = (i % 2 == 0) ? 'tomato' : 'gold';
    ctx.fillRect(i * 20, 0, 20, 200);
}
ctx.restore();                  // 자르기 해제

ctx.fillStyle = 'black';
ctx.font = '20px sans-serif';
ctx.fillText('원 밖의 글자', 210, 108);

    6자주 하는 실수

    restore()가 그림을 지워 준다고 생각한다. 되돌리는 것은 설정뿐이다.

    기대와 다른 코드
    ctx.save();
ctx.fillRect(0, 0, 100, 100);
ctx.restore();
// 사각형은 그대로 남는다
    그림을 지우려면
    ctx.clearRect(0, 0, canvas.width, canvas.height);

    save()와 restore()의 개수가 맞지 않는다. 반복문 안에서 save()만 하면 상자가 계속 쌓이고, 바꾼 설정도 계속 누적된다.

    잘못된 코드
    for (let i = 0; i < 4; i++) {
    ctx.save();
    ctx.rotate(Math.PI / 2);
    ctx.fillRect(0, 0, 100, 20);
}   // restore 없음: 회전이 쌓인다
    올바른 코드 (한 쌍씩)
    for (let i = 0; i < 4; i++) {
    ctx.save();
    ctx.rotate(i * Math.PI / 2);
    ctx.fillRect(0, 0, 100, 20);
    ctx.restore();
}

    설정을 바꾼 뒤에 save()한다. save()는 "그 순간"의 설정을 찍기 때문에, 되돌아가고 싶은 상태일 때 먼저 불러야 한다.

    잘못된 순서
    ctx.fillStyle = 'tomato';
ctx.save();        // tomato가 저장됨
ctx.fillRect(0, 0, 50, 50);
ctx.restore();     // 여전히 tomato
    올바른 순서
    ctx.save();        // 원래 색이 저장됨
ctx.fillStyle = 'tomato';
ctx.fillRect(0, 0, 50, 50);
ctx.restore();     // 원래 색으로 돌아옴

    save() 없이 restore()만 부른다. 오류는 나지 않지만 꺼낼 것이 없어서 아무 일도 일어나지 않는다.

    효과 없음
    ctx.fillStyle = 'tomato';
ctx.restore();
ctx.fillRect(0, 0, 50, 50);   // tomato
    확인하는 법
    console.log(ctx.fillStyle);
// restore 앞뒤에 찍어 보면 바뀌었는지 알 수 있다
