파괴적 메소드와 비파괴적 메소드

메소드를 실행한 뒤 원래 배열이 바뀌는가, 그대로인가. 이 한 가지만 구분하면 "분명히 정렬했는데 왜 그대로지?" 같은 버그 대부분을 피할 수 있다.

미리 알아야 할 것: 배열 [ ], 인덱스, let과 const, console.log

파괴적: 원본이 정렬된다arr.sort();
비파괴적: 정렬된 새 배열을 돌려준다let sorted = arr.toSorted();

1무엇이 다른가

파괴적 (mutating)

원본 노트에 바로 고쳐 쓰기

메소드가 원래 배열 자체를 바꾼다. 고치기 전 모습은 남지 않는다.

비파괴적 (non-mutating)

복사본을 만들어 고쳐 쓰기

원래 배열은 그대로 두고, 결과를 새 값으로 돌려준다. 돌려받은 값을 변수에 담아야 쓸 수 있다.

파괴적 sort()

let arr = [3, 1, 2];
arr.sort();

console.log(arr);
// [1, 2, 3]  ← 원본이 바뀌었다

비파괴적 toSorted()

let arr = [3, 1, 2];
let sorted = arr.toSorted();

console.log(arr);     // [3, 1, 2]  ← 그대로
console.log(sorted);  // [1, 2, 3]  ← 새 배열

toSorted(), toReversed(), toSpliced(), with()는 2023년에 추가된 메소드다. Chrome·Edge 110, Firefox 115, Safari 16 이상에서 쓸 수 있다.

2실험대: 직접 눌러 보기

버튼을 누르면 arr에 그 메소드를 실행한다. 실행 전과 후의 arr, 그리고 메소드가 돌려준 값(반환값)을 비교해 보자. 파괴적 메소드를 연달아 누르면 바뀐 결과가 계속 쌓인다.

파괴적 원본을 바꾼다

let arr = [3, 1, 4, 1, 5];

      3배열 메소드 목록

      "반환값" 칸을 꼭 같이 보자. 파괴적 메소드는 바뀐 배열이 아니라 엉뚱한 값을 돌려주는 경우가 많다.

      짝으로 외우기

      파괴적 메소드 네 개에는 같은 일을 하는 비파괴적 짝이 있다. 이름 앞에 to가 붙으면 비파괴적이다.

      • sort()toSorted()
      • reverse()toReversed()
      • splice()toSpliced()
      • arr[i] = 값with(i, 값)

      짝 메소드가 없는 오래된 브라우저에서는 [...arr].sort()처럼 먼저 복사한 뒤 파괴적 메소드를 쓰면 같은 효과가 난다.

      4문자열 메소드는 모두 비파괴적

      자바스크립트의 문자열은 한 번 만들면 바꿀 수 없다. 그래서 toUpperCase(), trim(), replace(), slice() 같은 문자열 메소드는 모두 새 문자열을 돌려줄 뿐이고, 원래 변수는 그대로다.

      효과 없음 반환값을 버렸다

      let name = '  kim  ';
name.trim();
name.toUpperCase();

console.log(name);
// '  kim  '  ← 하나도 안 바뀌었다

      올바름 반환값을 다시 담았다

      let name = '  kim  ';
name = name.trim();
name = name.toUpperCase();

console.log(name);
// 'KIM'

      5자주 하는 실수

      비파괴적 메소드를 부르고 결과를 받지 않으면 아무 일도 일어나지 않은 것과 같다.

      잘못된 코드
      let scores = [70, 95, 80];
scores.toSorted();
console.log(scores);
// [70, 95, 80]
      올바른 코드
      let scores = [70, 95, 80];
let sorted = scores.toSorted();
console.log(sorted);
// [70, 80, 95]

      push()는 배열이 아니라 길이를 돌려준다. 결과를 다시 담으면 배열이 숫자로 바뀐다.

      잘못된 코드
      let fruits = ['사과', '배'];
fruits = fruits.push('귤');
console.log(fruits);
// 3
      올바른 코드
      let fruits = ['사과', '배'];
fruits.push('귤');
console.log(fruits);
// ['사과', '배', '귤']

      sort()의 결과를 새 변수에 담아도 복사본이 생기지 않는다. 두 변수가 같은 배열을 가리킨다.

      잘못된 코드 (원본을 남기고 싶었다)
      let original = [3, 1, 2];
let sorted = original.sort();
console.log(original);
// [1, 2, 3]  ← 원본도 정렬됨
      올바른 코드
      let original = [3, 1, 2];
let sorted = original.toSorted();
console.log(original);
// [3, 1, 2]

      =로 배열을 옮기면 복사가 아니라 같은 배열에 이름표를 하나 더 붙인 것이다. 한쪽을 파괴적 메소드로 바꾸면 다른 쪽도 바뀐다.

      잘못된 코드
      let a = [1, 2];
let b = a;
b.push(3);
console.log(a);
// [1, 2, 3]
      올바른 코드 (진짜 복사)
      let a = [1, 2];
let b = [...a];   // 또는 a.slice()
b.push(3);
console.log(a);
// [1, 2]

      const 배열도 파괴적 메소드로는 바뀐다. const가 막는 것은 다른 배열을 다시 넣는 것(=)뿐이다.

      오류 없음
      const list = [1, 2];
list.push(3);
console.log(list);
// [1, 2, 3]
      오류
      const list = [1, 2];
list = [1, 2, 3];
// TypeError: Assignment to constant variable.

      덤: sort()와 toSorted()는 기본적으로 숫자도 글자 순서로 정렬한다. 숫자 크기 순으로 정렬하려면 비교 함수를 넣는다.

      예상과 다른 결과
      [10, 9, 1].toSorted();
// [1, 10, 9]
      숫자 크기 순
      [10, 9, 1].toSorted(function (a, b) {
    return a - b;
});
// [1, 9, 10]

      6언제 무엇을 쓸까

      파괴적 메소드가 나쁜 것은 아니다. 원본을 바꾸는 것이 목적인지 아닌지에 따라 고른다.

      • 할 일 목록에 새 항목을 추가한다. 목록 자체가 바뀌어야 한다.파괴적 push()
      • 게임 점수 배열에서 1등을 뽑아 보여 주되, 입력 순서도 남겨 둬야 한다.비파괴적 toSorted()
      • 장바구니 가격 배열로 "할인가 목록"을 따로 만든다.비파괴적 map()
      • 함수에 배열을 받아서 처리한다. 함수를 부른 쪽의 배열은 건드리지 말아야 한다.비파괴적
      • 대기열에서 맨 앞 사람을 꺼낸다.파괴적 shift()

      헷갈리면 "이 배열을 다른 곳에서도 쓰고 있나?"를 물어보자. 쓰고 있다면 비파괴적 메소드가 안전하다.
