# 우리동네 보물찾기 — LLM Wiki

> `escapeRoom-Game/LLM-wiki.md`의 방탈출 게임 설계 원칙을 바탕으로 제작한 가족용 동네 탐험 게임 문서입니다.

## 1. 프로젝트 개요

**우리동네 보물찾기**는 동네 풍경 속 장소를 클릭하며 단서를 모으고, 퍼즐을 풀어 숨겨진 보물상자를 여는 웹 게임입니다.

원본 방탈출 프로젝트의 핵심 흐름인 다음 구조를 동네 탐험 테마로 확장했습니다.

```text
배경 장면
→ 클릭 가능한 오브젝트
→ 장소별 단서
→ 퍼즐 해결
→ 다음 장소 해금
→ 최종 암호 입력
→ 성공 엔딩 또는 Game Over/재도전
```

### 앱 파일

- 실행 파일: `우리동네_보물찾기.html`
- 저장 폴더: `게임/우리동네_보물찾기/`
- 실행 방법: HTML 파일을 브라우저에서 열기
- 기술 방식: 외부 프레임워크 없는 단일 HTML
- 구성: HTML + CSS + JavaScript 내장

## 2. 제작 목적

- 가족이 함께 즐길 수 있는 쉬운 탐험형 게임을 만든다.
- 평범한 동네를 관찰하고 장소와 단서를 연결하는 재미를 준다.
- AI 바이브코딩으로 기획서의 아이디어를 실제 플레이 가능한 웹앱으로 구현한다.
- 코딩을 몰라도 단일 HTML 파일을 실행해 결과물을 확인할 수 있게 한다.

## 3. 원본 LLM Wiki에서 계승한 설계 원칙

### 3.1 배경 위에 오브젝트를 배치한다

방탈출 게임과 같은 방식으로 하나의 장면 위에 여러 장소 오브젝트를 배치합니다.

- 우체통
- 공원
- 도서관
- 빵집
- 보물상자

기본 배경은 CSS 일러스트로 제공되며, 사용자가 원하는 이미지를 업로드해 배경을 바꿀 수도 있습니다.

### 3.2 움직이는 오브젝트로 탐색을 유도한다

각 장소 오브젝트에는 작은 움직임을 적용했습니다.

- 위아래로 살짝 떠오르는 애니메이션
- 이모지와 라벨을 결합한 핫스팟
- 잠긴 장소는 흐리게 표시
- 해결된 장소는 초록색 표시와 체크 표시

이렇게 하면 사용자는 어떤 장소를 눌러야 하는지 직관적으로 파악할 수 있습니다.

### 3.3 장소를 클릭해 대화와 퍼즐을 실행한다

각 오브젝트는 단순한 장식이 아니라 실제 게임 상태를 변경합니다.

- 우체통: 첫 번째 단서 제공
- 공원: 색깔 순서 퍼즐 실행
- 도서관: 숫자 단서 제공
- 빵집: 최종 암호 조합 제공
- 보물상자: 암호 입력 및 엔딩 실행

## 4. 게임 시놉시스

어느 날 우리동네에 숨겨진 보물지도가 사라졌습니다.

동네 우체통에서 발견한 편지는 보물이 **우리동네를 가장 잘 아는 사람**에게만 모습을 보인다고 알려줍니다. 플레이어는 공원, 도서관, 빵집을 차례로 탐험하며 단서를 모아 보물상자를 열어야 합니다.

핵심 메시지는 다음과 같습니다.

> 가족과 함께 동네를 천천히 관찰하면 평범한 하루도 멋진 모험이 됩니다.

## 5. 게임 화면 구성

### 5.1 상단 영역

- 게임 제목: 우리동네 보물찾기
- 간단한 설명
- `현재 힌트` 버튼
- `처음부터` 버튼

### 5.2 중앙 탐험 장면

- 하늘·언덕·집·나무·도로로 구성된 기본 동네 풍경
- 장소별 핫스팟 버튼
- 화면 하단의 탐색 안내 문구
- 사용자가 올린 배경 이미지로 교체 가능한 장면

### 5.3 하단 상태 영역

- 탐험 진행률
- 현재 수집한 단서

## 6. 장소와 퍼즐 설계

| 순서 | 장소 | 역할 | 해금 결과 |
|---|---|---|---|
| 1 | 동네 우체통 | 게임 시작, 첫 편지와 다음 장소 안내 | 햇살 공원 |
| 2 | 햇살 공원 | 파랑 → 노랑 → 빨강 색깔 순서 퍼즐 | 작은 도서관 |
| 3 | 작은 도서관 | 책갈피 숫자 `1` 발견 | 별빵집 |
| 4 | 별빵집 | 최종 암호 조합 안내 | 보물상자 |
| 5 | 보물상자 | 최종 암호 입력 | 성공 엔딩 |

## 7. 상세 플레이 흐름

### 7.1 우체통

플레이어가 처음 조사할 수 있는 유일한 장소입니다.

편지 내용:

> “보물은 우리동네를 가장 잘 아는 사람에게만 모습을 보여준단다.”

편지의 뒷면은 공원 미끄럼틀 아래에 색깔 단서가 있다는 것을 알려줍니다.

획득 단서:

```text
첫 번째 단서: 공원 미끄럼틀 아래의 색깔 순서
```

### 7.2 햇살 공원

색깔 타일을 순서대로 눌러야 합니다.

```text
파랑 → 노랑 → 빨강
```

순서를 틀리면 Game Over가 표시됩니다. 정답을 맞히면 숫자 `1`이 적힌 책갈피를 얻고 작은 도서관이 해금됩니다.

### 7.3 작은 도서관

세 번째 책에서 책갈피를 발견합니다.

책갈피의 숫자:

```text
1
```

이 숫자는 최종 암호의 두 번째 숫자이며, 다음 장소인 별빵집을 해금합니다.

### 7.4 별빵집

빵집 주인은 최종 암호의 조합 방법을 알려줍니다.

```text
우체통 옆 집의 번호 3
+ 책갈피의 숫자 1
+ 별빵집 간판의 별 7개
```

최종 암호:

```text
317
```

### 7.5 보물상자

수집한 단서를 순서대로 입력합니다.

- 숫자 키패드 제공
- 뒤로 지우기 버튼 제공
- 세 자리 암호 입력
- 정답이면 성공 엔딩
- 오답이면 Game Over 및 재도전 제공

## 8. 상태 관리 구조

앱은 JavaScript의 `state` 객체로 게임 진행 상태를 관리합니다.

```javascript
const state = {
  unlocked: new Set(['mailbox']),
  solved: new Set(),
  clues: [],
  colorIndex: 0,
  code: '',
  gameOver: false,
  won: false
};
```

### 주요 상태

- `unlocked`: 현재 접근할 수 있는 장소
- `solved`: 해결한 장소
- `clues`: 화면에 표시할 수집 단서
- `colorIndex`: 색깔 퍼즐의 현재 진행 위치
- `gameOver`: 실패 상태
- `won`: 성공 상태

### 장소 해금 규칙

```text
우체통 해결
→ 공원 해금
→ 색깔 퍼즐 해결
→ 도서관 해금
→ 책갈피 확인
→ 빵집 해금
→ 최종 암호 확인
→ 보물상자 해금
```

## 9. 오버레이와 상호작용

모든 장소의 대화와 퍼즐은 공통 모달 창에서 실행됩니다.

사용되는 구성 요소:

- `openModal()`: 모달 열기
- `closeModal()`: 모달 닫기
- `gameOver()`: 실패 화면 표시
- `reset()`: 게임 상태 초기화
- `showHint()`: 현재 진행 단계에 맞는 힌트 표시

모달은 다음 상황에서 사용됩니다.

- 우체통 편지
- 색깔 퍼즐
- 색깔 퍼즐 성공 안내
- 도서관 책갈피
- 빵집 최종 단서
- 보물상자 암호 입력
- 성공 엔딩
- Game Over

## 10. 실패와 재도전 설계

### Game Over가 발생하는 경우

- 공원 색깔 퍼즐의 순서를 틀린 경우
- 보물상자 암호를 잘못 입력한 경우

### 재도전

`다시 도전하기`를 누르면 다음 항목이 초기화됩니다.

- 해금된 장소
- 해결한 장소
- 수집한 단서
- 색깔 퍼즐 진행 위치
- Game Over 상태
- 성공 상태

초기 상태에서는 우체통만 조사할 수 있습니다.

## 11. 배경 이미지 변경 기능

기본 CSS 동네 풍경 외에 사용자가 직접 이미지를 올릴 수 있습니다.

처리 방식:

1. 이미지 파일 선택
2. `FileReader`로 브라우저 내부에서 이미지 읽기
3. `background-image`에 Data URL 적용
4. 기존 핫스팟과 퍼즐 구조는 그대로 유지

따라서 가족사진, 실제 동네 사진, 학교 주변 사진 등을 배경으로 사용할 수 있습니다.

## 12. 접근성과 반응형 설계

- 장소 오브젝트를 semantic `button`으로 구현
- `aria-label` 제공
- 키보드 포커스 표시
- 모바일 화면에서 핫스팟 크기 조정
- `prefers-reduced-motion` 설정 지원
- 모달 바깥 클릭과 `Escape` 키로 닫기 가능
- 외부 이미지가 없어도 기본 게임 플레이 가능

## 16. 재사용 가능한 제작 패턴

이 프로젝트는 다음과 같은 바이브코딩 템플릿으로 재사용할 수 있습니다.

```text
주제와 이야기 정하기
→ 장소/오브젝트 목록 만들기
→ 각 장소의 대화·힌트·퍼즐 정하기
→ 퍼즐 간 선후관계 정하기
→ HTML 단일 페이지로 구현
→ 브라우저에서 실제 플레이
→ 성공·실패·재도전 검증
```

핵심은 단순히 예쁜 화면을 만드는 것이 아니라, 다음 요소를 하나의 흐름으로 연결하는 것입니다.

- 장면
- 오브젝트
- 클릭 이벤트
- 단서
- 퍼즐
- 상태 변화
- 성공과 실패
