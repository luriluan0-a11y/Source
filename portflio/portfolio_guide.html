포트폴리오 구조 설계 가이드

아래 항목을 차례대로 채우면 포트폴리오의 뼈대가 완성됩니다. 다 작성한 뒤 마크다운(.md) 파일로 내려받기 버튼을 누르세요.

작성 내용은 이 브라우저에만 자동 저장됩니다. 다른 기기로 옮기려면 반드시 파일로 내려받아 두세요.

작성 원칙 두 가지

  • 최신순 정렬 — 기간이 들어가는 항목(학력·경력·프로젝트)은 가장 최근 것이 맨 위로 옵니다. 시작 연월을 적어두면 내려받을 때 자동으로 정렬됩니다.
  • 직무 우선순위 배치 — 프로젝트 경험은 지원 직무와 관련이 깊은 것을 위로 올립니다. 예를 들어 QA 직무라면 테스트 케이스(TC)·버그 리포트 경험을 위로, 순수 개발 경험은 아래로 내립니다. 각 프로젝트의 정렬 우선순위 값과 ▲▼ 버튼으로 순서를 조정하세요.
1

나를 설명하는 한 마디

읽는 사람이 3초 안에 “이 사람은 이런 사람이구나”를 느끼도록, 강점을 담은 한 문장으로 표현합니다.

예시
• 숨겨진 버그를 찾아내는 버그 탐색자
• 누구나 함께 일하고 싶어하는 Unity 개발 신동
직책·기술·성향 중 하나를 강조하면 좋습니다. 20자 안팎을 권장합니다.
2

기본 정보

개인정보는 연락에 꼭 필요한 최소한만 적습니다. 주민번호·상세 주소·사진은 넣지 않습니다.

평소 확인하는 주소로. 이름 기반의 단정한 주소를 권장합니다.
3

학력

최종 학력부터. 시작 연월을 적으면 최신순으로 자동 정렬됩니다.

고등학교부터 작성합니다. 오래된 학교부터 입력해도 시작 연월을 적어두면 내려받을 때 최신순으로 자동 정렬됩니다.
4

경력

인턴·아르바이트·계약직도 직무와 관련 있으면 적습니다. 최신순 자동 정렬됩니다.

한 일을 동사 + 결과로 적습니다. 예: “회원 가입 플로우 테스트 케이스 120건 작성, 출시 전 결함 18건 발견”
5

프로젝트 경험

지원 직무와 관련이 깊은 프로젝트를 위로 배치합니다. 정렬 우선순위 숫자가 작을수록 위로 오고, 같은 값이면 최신순입니다. ▲▼ 버튼으로도 조정할 수 있습니다.

각 프로젝트는 무엇을 / 어떤 역할로 / 어떤 기술로 / 어떤 성과 순서로 적으면 읽기 쉽습니다.
QA 지원이라면 “테스트 설계”, “버그 리포트” 성격의 항목을 위로, “기능 개발” 성격은 아래로.
